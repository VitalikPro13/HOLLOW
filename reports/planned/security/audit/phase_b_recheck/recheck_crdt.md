Open items, one line each:
- PARTIAL 0.5 / inherited by every replay row: a legacy-anchored (32-hex, un-checkpointed) server still has the 1000-op dedup cap and arrival-order apply, so replays and reorders by an Olm peer or sync responder still work there until the owner's 0.12 client signs a checkpoint; documented as a HOL-SEC-047 variant, no AR entry.
- PARTIAL A-05: same legacy residual on the sync path, plus a legacy join completing with zero admitted ops (`swarm.rs:9306`).
- PARTIAL A-06: on a legacy server joined with an `owner=` pin, only the snapshot's Owner is checked; a hostile member holding a door can hand the joiner its own role map and withhold the owner's checkpoint until an honest member serves it; not covered by AR-10.
- PARTIAL A-09: `MemberKickBroadcast` (Olm) is not tied to a CRDT removal of us; any member device with KICK_MEMBERS that outranks us can make our node delete the server locally while the CRDT still lists us.
- GAP B-05: `ChannelAdded.channel_id` has no grammar check at ingest, so a MANAGE_CHANNELS holder can create the reserved `~join` id that `types.rs:879-882` assumes impossible (insider, availability).
- NOT CARRIED: CRDT-S4's "kick without a CRDT op" half (now A-09 PARTIAL); CRDT-S17's channel-id grammar half (now B-05 GAP).
- Other observations (not verdicts): HLC witness now runs before `op_allowed` (`fold.rs:180-182`), so any Olm peer can push our clock up to +5 min with a self-signed op for a server we hold; target-side checks (`get_role`, `is_member`, `is_banned` of a target) still go through the process-global resolver, so they can differ per replica; MLS-first `ServerDeleted` never removes the MLS group; carried-path self-ban emits only `MemberLeft` while the MLS path tears down; `admit_remote_rejects_*` tests exercise a `#[cfg(test)]` copy, not `stateless_check`.
