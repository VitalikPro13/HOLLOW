# Phase B re-check: authz_files.md (files, vault, recovery pool, share, asset rail)

Re-checked 2026-10-02 against the working tree (HEAD `d16deefe`), read-only. Paths are
relative to `rust/hollow_core/src/`. Every citation below was read in the current file.

Transport facts used throughout (read once, cited here):
- `FileRequest`, `FileUnavailable`, `PublicFileHeader`, `EmoteRequest`, `EmoteAssets` are
  `Lane::Carried` (`node/types.rs:4104-4115` `| Self::FileRequest { .. }` ... `=> Lane::Carried,`);
  a plaintext copy is dropped before any handler (`node/swarm.rs:5181` `} else if msg.lane() != Lane::Relay {`
  -> "it rides Olm only"). So `peer_str` on those arms is the Olm-authenticated device, not a relay `from`.
- Share control is `Lane::Share`, recovery is `Lane::Recovery` (`node/types.rs:4120-4129`), each only inside
  its sealed wrapper.
- WS binary stream frames are device-sealed: `node/swarm.rs:4528`
  `let data = match super::frame_auth::open(&data, &from, &room, delivery, now_ms) {`.
- MLS envelopes must name the decrypting group: `node/swarm.rs:10553`
  `if !crate::node::crypto_handler::mls_envelope_fits_group(`; a FileHeader with no `sid` is `Direct`
  (never valid in a group) `node/types.rs:4278-4280` `Self::FileHeader { inner } => match &inner.sid { ... None => Direct,`.
