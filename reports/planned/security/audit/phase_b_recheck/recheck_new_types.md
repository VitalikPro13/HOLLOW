# Phase B re-check: inbound types and ingest paths with NO evidence section

Read-only pass, 2026-10-02, against the current tree (HEAD d16deefe + working tree).
Paths are relative to the repo root; `swarm.rs` etc. mean `rust/hollow_core/src/node/<file>`
unless a directory is given. Attacker model per the brief (hostile relay; peers with valid
keys for their own identity).

## Method

1. Enumerated every variant of `HavenMessage` (`node/types.rs:1514`) and `MessageEnvelope`
   (`node/types.rs:3144`), every `CrdtPayload` (`crdt/operations.rs:146`), every roster
   statement kind (`identity/roster.rs:45-156`), every relay JSON `type` in
   `relay-uws/src/ws_handler.cpp:2487-2660` plus the pre-auth frames (`auth_frame.h`), every
   binary opcode (`ws_handler.cpp:2846-2866`), every `WsEvent` (`ws_client.rs:165-224`), the
   forwarder's dispatch (`forwarder/signaling.rs`), and the push fetch node (`fetch.rs`).
2. Grepped all nine `phase_b_evidence/authz_*.md` for each name and for each `### ` header.
   A name counts as covered when a `### ` section names it (directly or in a group header
   such as A-MED-06 "SdpAnswer / Ice ..."). Mentions outside a header do not count.
3. For each uncovered item: read the dispatch site and followed into the deciding function.

Covered and NOT re-verified here (they belong to the per-area agents): every other
`HavenMessage`/`MessageEnvelope` variant, the 39 older `CrdtPayload` variants (B-01..B-39),
every other relay JSON type and all opcodes, every other `WsEvent`, the forwarder `fwd_*`
set (A-MED-09..11), and `fetch.rs` (only covered types: Encrypted, MlsChannelMessage,
PublicChannelMessage, DirectMessage, EditMessage, LinkPreviewSet, FileHeader, ChannelMessage,
kill frames).
