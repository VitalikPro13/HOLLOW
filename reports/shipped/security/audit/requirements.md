# Hollow security requirements, 0.14

This is the list of security requirements Hollow holds itself to in 0.14, written for
external reviewers. Each requirement says what must hold, where
the code enforces it, and which test proves it. The promises users read are in
`claims.md` (C-01 to C-39); every requirement here names the claims it serves. What we
knowingly leave open is in `accepted_risks.md`, and every finding with its fix is in
`findings/`.

Status: written 2026-11-05 at `56587ca2`, brought up to date on 2026-11-15 at `ad38a14e`
with every 0.14 track; it describes the 0.14 release. Paths are relative to
`rust/hollow_core/src/` unless they start with `relay-uws/`, `lib/` or `test/`. A test
named here exists in that tree unless it is marked *planned*. Section 11 lists what is
still open at the 0.14 release.

## How to read a row

- **Requirement**: one sentence that a test can check.
- **Enforced in**: the module or function that refuses what breaks it. Where a rule lives in
  both the app and the relay, both are named, and each has its own test.
- **Proven by**: tests that fail when the rule is taken out. Most were written to fail
  first, and the security mutation passes remove each rule again to check that a test
  notices (`mutation_passes/`). "Relay" marks a C++ unit test, "live" a case of the
  relay's live suite (`relay-uws/test/run_live.sh`), "harness" a multi-node test.

Three rules run through every row. A signature proves who sent something, never that they
may do it. A failed check refuses; it never logs a warning and carries on. Live traffic is held to
every rule, while history from sync is checked for authorship but may predate a later
mute or role change.
