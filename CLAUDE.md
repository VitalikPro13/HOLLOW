# HOLLOW: Project Instructions for Claude Code

## What Is This
Distributed, encrypted Discord alternative: no central servers, members host it. `HOLLOW_PLAN.md` = architecture, phases, TODO.

## Tech Stack
- **UI:** Flutter (Dart), 6 platforms
- **Backend:** Rust via `flutter_rust_bridge` v2.11.1
- **Networking:** WSS relay (signaling, text/CRDT/MLS) + WebRTC data channels (files) + WebRTC media.
- **E2EE:** vodozemac (Olm) DMs, OpenMLS 0.9 servers, SFrame (AES-128-GCM) media
- **Local DB:** SQLCipher
- **Identity:** Ed25519 via BIP-39 mnemonic
- **Org ID:** com.anonlisten · **Project:** hollow

## Project Structure
- `lib/`: `main.dart` entry; `src/core/` models+providers+services, `src/theme/`, `src/ui/`.
- `rust/hollow_core/src/`: `api/` FFI (frb scans these); `node/` swarm.rs + focused modules (test_harness cfg(test)); `crypto/` Olm+MLS (store.rs = CryptoStore); `identity/`; `storage/` SQLCipher.
- `reports/`: `planned/`|`shipped/`|`reference/` per area; index `reports/README.md`.
- `relay-uws/` production relay (native TLS). `packages/flutter_webrtc/` FORK 1.5.2, libwebrtc m144 = OUR patched build, `screen_audio_capturer.exe` = SEPARATE target. `legal/` policy+terms.

## Key Architecture Notes
- **Multi-node harness (`node/test_harness.rs`) = PRIMARY testing for distributed logic;** ALWAYS verify ring-1/ring-2 changes there; it does NOT cover media/native/relay C++ or device->master attribution (process-global resolver). `feedback_harness_first_testing`.
- **Node modules:** `swarm.rs` = event-loop dispatcher; domain logic in focused modules as `handle_*()`; types in `types.rs`. No SwarmContext; pass state vars individually (`feedback_swarmcontext_borrow`). New envelope variants -> the owner's `handle_envelope_*()` (`feedback_envelope_dispatch_pattern`).
- **Persistence actors:** `CrdtStore` + `CryptoStore` own long-lived SQLCipher conns in spawn_blocking threads, fire-and-forget mpsc (batched per server). NEVER `MessageStore::open()` in a sync handler or on the event loop. `feedback_sqlcipher_open_hygiene`.
- **Peer state in swarm.rs:** `ws_room_peers` + `synced_peers`; PeerJoined -> key exchange + sync; 30s keepalive in ws_client.rs.
- **Relay domain:** `relayDomainProvider` + `set_relay_url()`, default `relay.anonlisten.com`; ALL WS/signaling/STUN/TURN URLs derive from it.
- **CRITICAL: Dart traps that fail SILENTLY**; read before debugging layout or a stuck Future. `feedback_dart_patterns`, `feedback_badge_stack_clips_avatar_frame`.
- **Logging:** `hollow_log!` -> stderr + `hollow_debug.log`; `hollow_crash.log` = Flutter errors. **NEVER `eprintln!`/`println!` in hollow_core:** a dead stderr (closed terminal) PANICS every line, killing the node while the window lives. `feedback_linux_stderr_epipe_panic`.
- **CRITICAL: user-visible text carries ZERO em dashes** (UI, docs, legal, Rust errors, website); comments/logs exempt. NEVER a colon in its place, write naturally. Settings labels = SENTENCE case; Title Case only for section/doc titles, permission names, proper nouns. **Every body of user-facing copy (changelog, news, store, website, help, legal) goes through the `sepia` skill BEFORE Vitalik sees it; changelog = ONE plain sentence per change.** `feedback_vitalik_writing_voice`.
- **Storage & profiles (#47):** data root `dirs::data_dir()/hollow` (override `set_data_dir()`/`HOLLOW_DATA_DIR`); desktop precedence env > `--portable` > profiles.json PIN > marker > `hollow_data` WITH identity (NEVER `data`); keychain = PER-PROFILE slots. `project_portable_mode`, `project_issue47_sframe_keystore_fix`.
- **Identity at-rest protection:** two opt-in modes: password (blocks launch) or OS keychain (silent). `unlock_identity()` before any identity/DB op. `project_identity_protection`.
- **Deep links:** `hollow://` on all 6 platforms via `DeepLinkService` (init pre-runApp). Invites COPY `webServerInviteLink()` (FRAGMENT url, id never hits server logs); ALL link input bars parse via `inviteIdFromInput`/`classifyHollowLink`. `project_deep_linking`.
- **Self-hosting (`relay-uws/SELF_HOSTING.md` = THE guide, ONE `.env`):** TURN URIs from `--domain`; invites stamp the SENDER's relay (`required relay:` on every builder); a differing relay = ONE dialog `relay_switch_dialog.dart`, NEVER auto-switch; `relayStatusProvider` null = unknown. `project_self_hosting_overhaul_2026_09`.
- **Relay access keys:** SELF-HOSTED opt-in only (`keys.json`, app caches `set_license_key()`); the official relay keeps them OFF, open to all, no alpha/limited-access copy. `project_official_relay_open`.

## Relay
- **Relay:** uWebSockets C++ (`relay-uws/`). NO rate limits/byte quotas, NEVER lower `maxPayloadLength` (64MB). Topics `0x07`, broadcast `0x03`. EVERY binary handler gates on SENDER room membership + validates the peer-id shape (`is_peer_id_shape`); pre-auth frames ONLY via `parse_auth_frame` (a throw into uSockets kills the process); no limits before phase G; per-IP RAM = connection caps only via `ip_limit_key()` (v6 /64, unmap v4-MAPPED first). `feedback_relay_rules`, `project_relay_fairshare_turn_lock`.
- **CRITICAL: the relay box: every service runs as its OWN account (never `ubuntu`/sudo) in a systemd sandbox; the repo units ARE the box's units; secrets ONLY in root-only `EnvironmentFile`/`LoadCredential` (`Environment=` is readable by every account via `systemctl show`); nothing to disk (rsyslog drops `hollow-*`, `ufw logging off`); a denied syscall = EPERM, never kill (skips the snapshot). After any box change `sudo bash relay-uws/deploy/check-host.sh` prints only ok.** `project_relay_hardening_h`.
- **CRITICAL: every relay table a stranger can fill is BOUNDED and FAIR (`fair_share.h`):** each entry is charged to the writer's hashed address share (`socket_share`: v4 or v6 /48, hourly key, never persisted); a full table evicts the HEAVIEST share, never by age or identity (identities are free); byte budgets, nothing refuses. A new RAM registry joins it. `project_relay_fair_share`.
- **CRITICAL: relay offline delivery (availability cache):** anything for OFFLINE channel members MUST ride `0x07` topic frames (`0x03`/directs never enter rings); parked joins = the `~join` ring (park 3 s if the room is EMPTY, else 15 s), holding only sealed join boxes. Catch-up gates stamp ONLY once `ws_room_peers` holds the room; public-channel ops send BOTH 0x03 and the topic. `project_relay_availability_cache`, `project_pending_server_joins`, `feedback_once_per_connection_gate_precondition`.
- **CRITICAL: relay restart persistence:** buffers/opt-ins/rings/push tokens/join locks ride systemd's fd store as a memfd on SIGTERM (`snapshot.cpp`; NEVER a file or disk; no swap, no apport, `LimitCORE=0`); snapshot BEFORE `app.close()`; any new RAM registry an OFFLINE peer cannot re-send joins `snapshot_codec.h` (bump VERSION). `project_relay_restart_persistence`.
- **CRITICAL: relay auth v2 + authority (A-D4):** clients log in by `auth_hello` -> nonce -> a signature over the relay's DOMAIN, the nonce and every flag (`auth_frame.h` = `ws_client::auth_v2_message`, pinned); fetch sockets never take a full socket's slot and are never listed; an `inbox:` room shows only PROVEN owners (mailbox deposits reach them live); ring control is signed by the join lock's CHANGE key (`ring_auth`), a legacy server's ring topics are `{owner}.{channel}` (`ring_auth::topic`, every send/subscribe/catch-up); nickname claims are master-signed and a lookup sends nothing until the person confirms. Once 0.12 ships, turn off `ACCEPT_AUTH_V1`, `ACCEPT_UNSIGNED_RING_CONTROL`, `ACCEPT_UNSIGNED_NICKNAME_CLAIMS` and redeploy. `project_relay_a_d4`.
- **CRITICAL: relay topic subscriptions are PER-SOCKET:** ws_client replays them on every reconnect; desktop's subscribe-listener microtask-defers past the selection batch (channel is written BEFORE server). `feedback_channel_topic_subscriptions`.
- **CRITICAL: WS sends: bounded + never silently discarded.** ALL ws_client.rs sink writes go via `bounded_send` (30s timeout): a raw `write.send()` on a wedged socket freezes the select loop incl. the watchdog. `send_command()` false -> break, buffer, reconnect. `feedback_ws_zombie_liveness_timeout`.
- **CRITICAL: `RoomMembers` = authoritative presence:** diff sets -> `PeerDisconnected` for vanished; `PeerLeft` refreshes suspect rooms; OUR OWN leave purges the room (`WsEvent::LeftRoom`); a stale self-left room silently blackholes targeted sends. `feedback_ws_presence_stale_rooms`.
- **CRITICAL: `WsEvent::Disconnected` purges sync-gating state + remote VC participants; `is_new` is NOT "a new socket"**: an unclean drop sends no `PeerLeft`, so reconnect work goes OUTSIDE it. `feedback_is_new_is_not_a_new_socket`.

## Crypto, identity, authority
- **CRITICAL: sig verification REJECTS, never logs;** `if sig.is_some()` IS the bypass. A body over 64 KiB (`MAX_MESSAGE_BYTES`) drops whole, NEVER clipped. LIVE enforces, backfill tolerates. `feedback_signature_enforcement_not_logging`.
- **CRITICAL: EVERY remote-reachable store write sits behind a gate (wiki `security_write_gates.md`; a row per new ingest path). A signature proves WHO, never MAY: every remote change (sync or live) touches an EXISTING row only via `change_may_touch_row`.** `project_close_all_known_holes_085`.
- **CRITICAL: message signing = `sign_message_versioned`, v2 or v3 iff `album` present (the payload picks; non-UUID album REJECTS); v1 GONE, NEVER a fallback (downgrade oracle).** Edit/delete sigs bind the row's FULL extras. New message-row paths MUST persist the SENDER's wire `order_us` + `album`; mint via `chat_clock::next_send_stamp_us()` BEFORE any async hop. `feedback_chat_clock_lamport`.
- **CRITICAL: Olm key exchange is DEVICE-signed + ENFORCED** (`REQUIRE_SIGNED_KEY_EXCHANGE`): verify sig/recipient/freshness/device-in-signed-list BEFORE session creation; glare keeps the LOWER device's session, replaced ones RETIRE (decrypt-only). - **CRITICAL: new `CrdtPayload` variants emit `ServerUpdated` in BOTH match blocks** (`handle_envelope_crdt_op` + `handle_incoming_request`); never fall into `_ =>` (emits `SyncCompleted`, no provider invalidation).
