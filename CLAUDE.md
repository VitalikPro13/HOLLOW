# HOLLOW: Project Instructions for Claude Code

## What Is This
Distributed, encrypted Discord alternative; no central servers, members host it. `HOLLOW_PLAN.md` = architecture, phases, TODO.

## Tech Stack
- **UI:** Flutter 3.47.9 (Dart), 5 platforms, no web
- **Backend:** Rust via `flutter_rust_bridge` v2.11.1
- **Networking:** WSS relay (signaling, text/CRDT/MLS), WebRTC data channels (files) + media.
- **E2EE:** vodozemac 0.11 (Olm) DMs, OpenMLS 0.9 servers, SFrame (AES-128-GCM) media
- **Local DB:** SQLCipher 4.20 (rusqlite 0.42)
- **Identity:** Ed25519 via BIP-39 mnemonic
- **Org ID:** com.anonlisten · **Project:** hollow

## Project Structure
- `lib/`: `main.dart` entry; `src/core/` models+providers+services, `src/theme/`, `src/ui/`.
- `rust/hollow_core/src/`: `api/` FFI (frb scans); `node/` swarm.rs + modules; `crypto/` Olm+MLS; `crdt/`; `identity/`; `storage/` SQLCipher.
- `reports/`: `planned/`|`shipped/`|`reference/` per area; index `reports/README.md`.
- `relay-uws/` production relay (native TLS). `packages/flutter_webrtc/` FORK 1.5.2, libwebrtc m144 = OUR patched build (Win/Linux; Apple = stock WebRTC-SDK pod), `screen_audio_capturer.exe` = SEPARATE target. `legal/` policy+terms.

## Key Architecture Notes
- **Multi-node harness (`node/test_harness.rs`) = PRIMARY test of distributed logic;** ALWAYS verify ring-1/ring-2 changes there; not media/native/relay C++ or device->master attribution (process-global resolver). `feedback_harness_first_testing`.
- **Node modules:** `swarm.rs` = event-loop dispatcher; domain logic in focused modules as `handle_*()`; types in `types.rs`. No SwarmContext; pass state vars individually (`feedback_swarmcontext_borrow`). New envelope variants -> the owner's `handle_envelope_*()` (`feedback_envelope_dispatch_pattern`). A big new swarm arm boxes its future in its OWN frame (`BoxedStep`): Windows debug workers have 2 MiB, ~56 KiB spare.
- **Persistence actors:** `CrdtStore`, `CryptoStore` own SQLCipher conns (spawn_blocking), fire-and-forget mpsc. node/ reaches the message store ONLY via `MessageStore::lease` (warm pool, `storage/store_pool.rs`), NEVER `MessageStore::open()` there (floor `store_open_floor.rs` + harness guard). `feedback_sqlcipher_open_hygiene`. An event Dart answers by re-reading CRDT state waits for the commit (`reads_persisted_server_state`).
- **Peer state:** `ws_room_peers` + `synced_peers`; PeerJoined -> key exchange + sync; 30s keepalive.
- **Relay domain:** `relayDomainProvider` + `set_relay_url()` (default `relay.anonlisten.com`); ALL WS/STUN/TURN URLs derive from it.
- **CRITICAL: Dart traps that fail SILENTLY**: read before debugging layout or a stuck Future. `feedback_dart_patterns`.
- **Logging:** `hollow_log!` -> stderr + `hollow_debug.log`; Flutter errors -> `hollow_crash.log`. **NEVER `eprintln!`/`println!` in hollow_core:** a dead stderr (closed terminal) PANICS the node while the window lives. `feedback_linux_stderr_epipe_panic`.
- **CRITICAL: user-visible text carries ZERO em dashes** (UI, docs, legal, Rust errors, website); comments/logs exempt. NEVER a colon in its place. Settings labels = SENTENCE case; Title Case only for section/doc titles, permission names, proper nouns. **Every body of user-facing copy (changelog, news, store, website, help, legal) goes through the `sepia` skill BEFORE Vitalik sees it; changelog = ONE plain sentence per change.** `feedback_vitalik_writing_voice`.
- **Storage & profiles (#47):** root `dirs::data_dir()/hollow` (`set_data_dir()`/`HOLLOW_DATA_DIR`); desktop: env > `--portable` > profiles.json PIN > marker > `hollow_data` WITH identity (NEVER `data`); keychain PER-PROFILE. `project_portable_mode`, `project_issue47_sframe_keystore_fix`.
- **CRITICAL: identity at-rest protection:** password (blocks launch) or OS keychain (silent). Keychain = DEFAULT on the Win/mac OS data root only, after a typed phrase check (new) or the FULL phrase (existing); never silent, never Linux/portable/override; a missing key deletes nothing; legacy slot read-only. macOS keys ONLY in the data-protection keychain (`group.com.anonlisten.hollow.keys`), read only after the bundle self-check; legacy items: copy, read back, THEN delete by reference; every Apple keychain call names a group (HOL-SEC-187). `unlock_identity()` before identity/DB ops. `project_identity_protection`.
- **Deep links:** `hollow://` via `DeepLinkService` (pre-runApp). Invites COPY `webServerInviteLink()` (FRAGMENT url, id never hits server logs); link bars parse via `inviteIdFromInput`/`classifyHollowLink`. `project_deep_linking`.
- **Self-hosting (`relay-uws/SELF_HOSTING.md` = THE guide, ONE `.env`):** TURN URIs from `--domain`; invites stamp the SENDER's relay (`required relay:`); a differing relay = ONE dialog `relay_switch_dialog.dart`, NEVER auto-switch; `relayStatusProvider` null = unknown. Access keys (`keys.json`) = self-hosted opt-in; the official relay is open to all, no limited-access copy. `project_self_hosting_overhaul_2026_09`, `project_official_relay_open`.

## Relay
- **Relay:** uWebSockets C++ (`relay-uws/`). NO byte quotas or per-message limits: the breaker (`breaker.h`, ENFORCED since 0.14, `BREAKER_MODE=shadow` escape) charges work units, closes 1013, never drops a frame; handlers charge via its hooks, tables byte-bounded on `fair_share.h`; clients mirror it (`relay_pace.rs` + `breaker_vectors.json`, change both), waiting only when `enforced`. `send_budget.h` bounds HELD bytes, closing via `close_once` (1013, never 1008). NEVER lower `maxPayloadLength` (64MB). Topics `0x07`, broadcast `0x03`. EVERY binary handler gates on SENDER room membership + `is_peer_id_shape`; pre-auth frames ONLY via `parse_auth_frame` (a throw into uSockets kills the process); client JSON ONLY via `client_json::parse` (depth 32; recursive dump/copy overflows the stack, HOL-SEC-128); per-IP RAM = connection caps only via `ip_limit_key()` (v6 /64, unmap v4-MAPPED first); connection limits are operator settings (`conn_limits.h`), a refusal closes 1008. `feedback_relay_rules`, `project_relay_fairshare_turn_lock`.
- **CRITICAL: the relay box: every service = its OWN account (never `ubuntu`) in a systemd sandbox (repo units ARE the box's); secrets ONLY in root-only `EnvironmentFile`/`LoadCredential` (`Environment=` shows in `systemctl show`); nothing to disk (rsyslog drops `hollow-*`, `ufw logging off`); a denied syscall = EPERM, never kill (skips the snapshot). After any box change `check-host.sh` prints only ok.** `project_relay_hardening_h`.
- **CRITICAL: every relay table a stranger can fill is BOUNDED and FAIR (`fair_share.h`):** each entry is charged to the writer's hashed address share (`socket_share`: v4 or v6 /48, hourly key, never persisted); a full table evicts the HEAVIEST share, never by age or identity (identities are free); byte budgets, nothing refuses. A new RAM registry joins it. `project_relay_fair_share`.
- **CRITICAL: relay offline delivery (availability cache):** anything for OFFLINE channel members MUST ride `0x07` topic frames (`0x03`/directs never enter rings); parked joins = the `~join` ring (park 3 s if the room is EMPTY, else 15 s), holding only sealed join boxes. Catch-up gates stamp ONLY once `ws_room_peers` holds the room; public-channel ops send BOTH 0x03 and the topic. `project_relay_availability_cache`, `project_pending_server_joins`, `feedback_once_per_connection_gate_precondition`.
- **CRITICAL: relay restart persistence:** buffers/opt-ins/rings/push tokens/join locks ride systemd's fd store as a memfd on SIGTERM (`snapshot.cpp`; NEVER a file or disk; no swap, no apport, `LimitCORE=0`); snapshot BEFORE `app.close()`; any new RAM registry an OFFLINE peer cannot re-send joins `snapshot_codec.h` (bump VERSION). `project_relay_restart_persistence`.
- **CRITICAL: operator denylist (relay `deny_list.h`, `node/relay_denial.rs`):** refuses listed servers/meetings, identities (+ devices its fold counts) and networks; deletes nothing. A client takes a refusal ONLY for its own servers, pending joins, guest rooms, meetings (never inbox/DM/own/fwd/link/share rooms); refused = nothing scoped leaves (sealing checks twice), no MLS commit, our ops wait under a saved mark (`unsent_ops`) for the lift; a refused login never switches relays. `project_relay_denylist_and_notice_policy`, wiki §66-67.
- **CRITICAL: relay auth v2 + authority (A-D4):** login = `auth_hello` -> nonce -> a signature over the relay's DOMAIN, nonce and every flag (`auth_frame.h` = `ws_client::auth_v2_message`, pinned); stamps the RELAY judges (login, ring control, nickname claims) use `relay_clock`, anything a PEER judges (message ts, HLC, seals, roster, kill orders) NEVER does; fetch sockets never take a full socket's slot, never listed; an `inbox:` room is owned ONLY by devices the relay's fold of that identity's rosters counts (ID-1R: joins carry `inbox_roster`, a removal or newer recovery shown once sticks, demotion at once, mailbox deposits reach owners live; `roster.h` mirrors `identity/roster.rs`, change both + `roster_vectors.json`); ring control is signed by the join lock's CHANGE key over `hollow-ring2` naming the relay (`ring_auth`; no `"v":2` = no parse, ring1 + its switch DELETED in 0.14), a legacy server's ring topics are `{owner}.{channel}` (`ring_auth::topic`, every send/subscribe/catch-up); nickname claims master-signed, a lookup sends nothing until confirmed; `discover_peers` answers only the presence digest. v1 auth does not parse, unsigned ring control only refreshes, unsigned claims and `inbox_proof` prove nothing. `project_relay_a_d4`, `project_id1r_relay_rosters`.
- **CRITICAL: relay topic subscriptions are PER-SOCKET:** ws_client replays them on every reconnect (desktop listener timing: `rules_ui_flutter`). `feedback_channel_topic_subscriptions`.
- **CRITICAL: WS sends: bounded + never silently discarded.** ALL ws_client.rs sink writes go via `bounded_send` (30s timeout): a raw `write.send()` on a wedged socket freezes the select loop incl. the watchdog. `send_command()` false -> break, buffer, reconnect. `feedback_ws_zombie_liveness_timeout`.
- **CRITICAL: `RoomMembers` = authoritative presence:** diff sets -> `PeerDisconnected` for vanished; `PeerLeft` refreshes suspect rooms; OUR OWN leave purges the room (`WsEvent::LeftRoom`); a stale self-left room silently blackholes targeted sends. Presence rides batches (`presence_batch.h`); a `members` answer short of what we were told = rejoin for the full list; relay rooms leave ONLY via `erase_room` (§69). `feedback_ws_presence_stale_rooms`.
- **CRITICAL: resumable relay sessions count frames on BOTH ends (`RESUMABLE_SESSIONS_PLAN.md` §9, §11):** every relay-to-client stream frame goes through `send_stream`/`send_held` (ringed BEFORE the write), presence and kill signals never; ring mutations only via `session_bounds.h` (never `ring_push` while iterating); a new JSON type is classified in `session_vectors.json` + `relay_type_counts`/`client_type_counts` AND `relay_session.rs` at once, else resumes skip or repeat frames. `project_resumable_sessions_plan`.
- **CRITICAL: `WsEvent::SessionLost` purges sync-gating state + remote VC participants (`Suspended` keeps all; resumable sessions, `RESUMABLE_SESSIONS_PLAN.md` §9); `is_new` is NOT "a new socket"**: an unclean drop sends no `PeerLeft`, so reconnect work goes OUTSIDE it. `feedback_is_new_is_not_a_new_socket`.
- **CRITICAL: presence = app ON SCREEN (decision 6, plan §11.5):** an `inactive` session is HIDDEN (`PerSocketData::hidden`) from every presence list, announcement and online query; delivery never changes. A phone in a call/VC/meeting/lobby never goes inactive (`relayRealtimeProvider`); a backgrounded or socket-down device takes NO MLS turn (`crypto_handler::MlsTurn`) and answers no door ask or hidden join (frozen view). Bulk sends to one device go through `frame_budget` pacing, and a bucket drop is re-asked, never final. `project_resumable_sessions_plan`.

## Crypto, identity, authority

## MLS

- **CRITICAL: KeyPackages mint ONLY via `mint_key_package()`** (generate + persist, CI-guarded; else a restart orphans the private half, every Welcome fails). - **CRITICAL: MLS stand-in authority = STANDING (`node/standing.rs`):** owner away, every leader (committer, join answerer, catch-up responder, repairer, fork winner, subgroup/vault coordinator) = first ONLINE leaf holder by role tier, fold position (`MemberSpan.admitted`), id. - **CRITICAL: ONE device per identity commits in a group (`we_commit_for_our_identity`: lowest online device of ours holding a leaf there) and ONE founds a group none of ours holds (`may_found_group`, after its online siblings asked; an owner device asks its OWN siblings for its leaf, `send_join_leaf_ask`)**: batch, sibling re-add; KeyPackages go to EVERY device of the target identity (`send_key_package_to_identity_of`).
