# chat_pane_shared.dart -- Shared Chat-Pane Building Blocks

Primary file: `lib/src/ui/chat/chat_pane_shared.dart` (~660 lines). Created 2026-07-15 (Sonar item-3 session). The DM pane (`ChatPane`) and channel pane (`ChannelChatPane`) are structural twins; everything genuinely identical between them lives here so the twins cannot drift AND so Sonar CPD stops pairing them (memory s3776-build-method-decomposition rule 8). `chat_pane.dart` RE-EXPORTS the public helpers (`shouldGroup`, `shouldShowDateSeparator`, `DateSeparator`, `TypingIndicatorBar`, `TypingDots`) so existing consumers (mobile routes, archive viewers) keep importing `chat_pane.dart` unchanged.

**Rule for future work:** when adding UI that both panes need (or that mobile_chat_route duplicates), extend THIS file instead of copying between the panes. `mobile_chat_route.dart` ADOPTED it 2026-07-15 (its S3776 decomposition): imports this file directly (not the re-export) and uses `ChatReplyPreviewBar`, `StagedFilePreviewBar`, `StagedLinkArea`, `UnreadJumpPill`, `DateSeparator`, `shouldGroup`/`shouldShowDateSeparator`, `dateSeparatedChatRow`, `reversedChatList` (with `selectionArea: false`), `TypingIndicatorBar`, and `typingMastersFor`. All three chat surfaces now share one module.

## Moved helpers (were top-level in chat_pane.dart)

- `shouldGroup()` -- same-sender-within-5-min message grouping (DMs compare `isMe`; channels also `senderId`).
- `stickerTileCandidate()` / `stickerTilingFor()` -- whether a row may tile into its neighbours (sticker-only text, nothing else in the seam) and which seams actually tile. Feeds `tileWithPrev`/`tileWithNext` on both bubbles from all THREE panes; see wiki `emotes.md` > "Sticker Mosaics".
- `composerStickerButton()` -- third composer button beside emoji and GIF. PROVISIONAL placement: the button row is being rethought, so `StickerPickerBody` is host-agnostic and moving the panel is a change of host, not of picker.
- `shouldShowDateSeparator()` -- calendar-day change check.
- `DateSeparator` -- horizontal-rule date label ("Today"/"Yesterday"/"Month Day, Year").
- `TypingIndicatorBar` / `TypingDots` -- typing bar (1-3 names or "Several people"), dots ride `SharedTickers.typingDots`.

## Widgets

- `UnreadJumpPill` -- accent "N new messages" pill (replaced BOTH panes' private `_UnreadPill` copies). Props: `count`, `onTap`.
- `ChatReplyPreviewBar` -- reply-compose bar above the input (accent left border, sender line, optional 32px `gifAwareImage` thumb, cancel X). Props: `senderName`, `text`, `imagePath`, `onCancel`.
- `StagedFilePreviewBar` -- staged-attachment bar (48px thumb or file icon, name, remove X). Props: `filePath`, `fileName`, `isImage`, `onRemove`.
- `StagedLinkArea` -- renders `StagedHollowLinkCard` (hollow:// invite) OR `StagedLinkPreviewCard` (OG preview) OR `SizedBox.shrink()`. Props: `hollowLink`, `previewUrl`, `preview`, `previewLoading`, `onDismissHollowLink`, `onDismissPreview`. Both panes keep tiny `_dismissStagedHollowLink`/`_dismissStagedPreview` methods as the callbacks.
- `ChatOverlayToggleButton` -- the 24x48 chevron tab that pins/unpins the screen-share chat overlay. Used by ChatPane's screen-share layout AND both copies in voice_channel_pane.dart. Props: `overlaysVisible`, `pinned`, `onTap`, `onHoverEnter`, `onHoverExit`.

## Functions

- `gifAwareImage(path, {width, height})` -- `GifFileImage` for .gif else `Image.file`, BoxFit.cover (replaced both panes' private `_gifAwareImage`).
- `reversedChatList({context, listKey?, itemScrollController, itemPositionsListener, scrollOffsetController?, itemCount, indexByMessageId, itemBuilder, selectionArea = true, padding, scrollRail = true, onJumpToNewest?})` -- THE reversed-list shell: SelectionArea (context menu suppressed) > ScrollConfiguration (no scrollbars) > `ScrollablePositionedList.builder` with `reverse: true`, `initialScrollIndex: 0`, and the `findChildIndexCallback` keyed-row reuse logic. The vendored-list iron rules (feedback_reverse_chat_lists) now live in exactly ONE place; guarded by `test/widget/chat_list_element_reuse_test.dart`. Since 2026-07-26 the whole list is also wrapped in `ChatTextScale` — this is THE chokepoint for the "Chat Text Size" preference (issue #20), so DM, channel and mobile message surfaces scale together and cannot drift. Mobile passes `selectionArea: false` -- SelectionArea's touch long-press would fight `LongPressMessage` -- plus its own horizontal padding; `listKey`/`scrollOffsetController` are optional (mobile passes neither). Since 2026-08-21 (issue #54) it also hangs the scrollbar rail beside the list on DESKTOP via `chatListWithRail`; `onJumpToNewest` must be the pane's own `_scrollToBottom`, because the display list is frozen while reading and index 0 is not the newest message until that freeze is released.
- `typingMastersFor(WidgetRef ref, Set<String> typingPeers)` -- collapses typing DEVICE ids to masters and excludes anything that is "us" (the Step 9C/C1 robust self-filter: resolves-to-my-master OR sameIdentity OR one of `myDevicesProvider` OR the running device -- a cold-resolver sibling arrives as a raw device id, so a bare master compare misses it). Shared by `ChannelChatPane._buildTypingBar` and mobile `_TypingBar`; callers map the returned masters to display names themselves (channel pane uses server nicknames, mobile plain `displayNameFor`).
- `dateSeparatedChatRow({rowKey, timestamp, prevTimestamp, showHeader, child, railGutter = false, unreadDivider = false})` -- keyed row shell: computes showDate, adds group-header top padding, wraps in `KeyedSubtree(ValueKey(rowKey))` with the separator above. A row carrying BOTH a date and the unread line draws ONE merged rule (`UnreadDivider(date:)`), never two. **The wrapper Column is `CrossAxisAlignment.stretch`, not the default centre** -- a grouped continuation row shrink-wraps, so it drifted to the middle of the pane the moment a separator appeared above it (latent since the date separator was written: a new day almost always starts a new group, so the row under a date rule almost always has a header and fills the width by itself). Guarded by `test/widget/unread_divider_test.dart`.
- `chatDayLabel(date)` -- "Today" / "Yesterday" / "February 16, 2026". Shared by `DateSeparator` and by `UnreadDivider` when the two merge.
- `unreadDividerIndex({count, entrySeenId, messageIdAt, isMineAt})` -- chronological index of the row the "new messages" line goes above, or null. `entrySeenId` comes from `unreadMarkerProvider`. Two rules: **your own messages never open an unread run** (sending is not arriving), and an unrecognised pointer means everything in the loaded window is new (it fell off the front of the 200-row window).
- `chatComposerField(hollow, {controller, focusNode, hintText, onChanged})` -- the `HollowTextField` composer (emote-aware controller, autofocus, 5-line cap, 4000-char limit, no counter), wrapped in `ChatTextScale` so you type at the size you read (mobile's own `_MobileInputBar` is wrapped the same way at its call site).
- `composerEmojiButton(hollow, {onOpen})` -- emoji-picker button; `onOpen` receives the button's own BuildContext for picker anchoring.
- `chatInputBarShell(hollow, {flushTop, child})` -- input-bar Container; `flushTop` drops the top border when a reply/staged/preview bar sits above.

## The scrollbar rail (issue #54, 2026-08-21)

The chat feed had no scrollbar and no way to jump. `ScrollablePositionedList` has no pixel offset a normal `Scrollbar` can map onto (its position is "item N, aligned so far into the viewport"), so this is an INDEX scrollbar.

- `ChatScrollRail({itemCount, controller, positions, onJumpToNewest?})` -- `Column([cap, gap, Expanded(track), gap, cap])`: three segments of one width, evenly spaced, sharing `railSegmentFill()` (`hollow.textSecondary` at 0.10, 0.18 while hovered or dragging; 0.05 was tried first and vanished at 1x). **The track is exactly the thumb's travel.** An earlier version drew ONE groove across the rail's whole height with the caps inside its ends, which painted track over the `_kCapExtent` the thumb cannot enter -- pinned to the newest message the thumb stopped 22px above the bottom of the groove and that empty run read as "there is more below". `kRailSegmentGap` (4) is load bearing: the gap between cap and track is what proves the track stops where the travel stops, and `chat_scroll_rail_test.dart` asserts it exactly. `kRailEndInset` (8) keeps the whole thing clear of the header above and the composer below (they used to be flush: cap top y=125, header border y=124).
- `_RailCap` -- ALWAYS drawn, dimmed and inert at the end it points to, the way a native scrollbar greys its arrows. Hiding it resized the track between the caps and shifted the thumb every time you reached an end. Inert = no `onTap`, no tooltip, no semantic label, so nothing announces an action that would do nothing (and `find.bySemanticsLabel` still means "actionable", which is what the older tests assert). Its chevron is `size: kScrollGutter` -- EXACTLY the pill's width. At `size: 12` the icon's box is wider than the pill, gets clamped to it, and the glyph's own centring is thrown off: measured, pill columns 1246-1255 with ink on 1249-1254, i.e. visibly right of centre at 1x. Matching the box to the pill also renders crisper (whole pixels, no resampling). **Widget tests cannot catch this** -- the test font draws every glyph as a filled box -- so it is checked by driving the app and reading pixels. Desktop only; touch keeps fling scrolling and the unread pill (a 16px drag rail sits under the edge-swipe gesture and its caps are far under a comfortable tap target).
- `chatListWithRail({list, rail})` -- puts the rail in a column of its own to the RIGHT of the list. **Never a `Stack` overlay.** That shape was tried: it laid out and painted correctly and then never received a single pointer.
- `_RailMetrics.from(positions, itemCount)` -- thumb offset/extent from the visible index range; null when everything fits. Indexes are the REVERSED builder indexes (0 = newest, at the BOTTOM), so a HIGHER index is further UP the track. That inversion is where the bugs live: the first drag mapping was flipped and only `test/widget/chat_scroll_rail_test.dart` caught it.
- `kChatRailWidth` (18 = `kWindowEdgeDeadStrip` + `kScrollGutter`) / `kWindowEdgeDeadStrip` (8) -- the gutter, and the inert margin the rail keeps between its controls and the window's outer edge. The frameless window's resize border eats pointer events in those outer pixels (memory `feedback_window_edge_dead_strip`); a control centred in a rail that hugs the edge is simply dead while every widget test passes. The 10px that are left is `kScrollGutter`, the same live gutter every other scrollable in the app reserves, and the thumb is FLUSH RIGHT in it (`left: constraints.maxWidth - 6`) so it lands where `HollowScrollBehavior` puts every other thumb. It was 22 with the thumb centred in the live strip until 2026-08-21; that left 12px of dead space to its right and put it 4px from the own-message accent bar. Guarded by "the thumb hugs the live edge of the gutter, not its middle" in `chat_scroll_rail_test.dart`.
- `OwnMessageMarker` / `markedAsOwn({isMe, row})` / `kOwnMessageBarWidth` (3) / `kOwnMessageBarInset` (4) -- the accent pill marking your own messages, wrapped around the row by both bubbles. A POSITIONED pill in a Stack, not a border: it runs the row's full height (a grouped run is several touching rows, and any vertical inset breaks it into a dashed line) and floats `kOwnMessageBarInset` inside the chat's left margin, opposite the rail's groove in the margin on the other side. It has moved twice, both times for a collision: `Border(right:)` put it 4px from the scroll rail's thumb (one confused double rule), `Border(left:)` welded it to the divider against the channel list so it read as a highlight on the PANEL. **A `Border` also INSETS its own Container's child** -- that shifted every own-message avatar 2px right of everyone else's until the row gave it back out of its padding; a positioned pill costs the row no layout, so that cannot recur. Guarded by `test/widget/message_accent_bar_test.dart`.
- `kChatRuleEndInset` (2) -- right-end padding for the date separator on a list that carries the rail, passed as `dateSeparatedChatRow(railGutter: true)` from the two DESKTOP panes only (mobile and the pinned-message list have no rail and stay symmetric). The rule is the only thing in a chat that draws all the way across, so its ends are where an unbalanced gutter shows: symmetric `HollowSpacing.lg` put it 16px from the pane's left edge and 34px from its right. 2 + `kChatRailWidth` lands the right end at 20. Guarded twice in `chat_scroll_rail_test.dart` -- a widget test that `railGutter` reaches the separator, and a pure-arithmetic one that fires if `kChatRailWidth` changes without revisiting this.
- Why the caps live in the gutter at all: the message hover action bar is an `OverlayEntry` centred on whatever row the pointer is over and right-aligned to it, so it covers anything floating INSIDE the list. The jump controls started as round buttons over the bottom-right of the list and the last message's bar sat on top of them.

The guest pane (`guest_chat_pane.dart`) builds its own list and calls `chatListWithRail` by hand; the DM, channel and mobile surfaces get it through `reversedChatList`.

## The "new messages" line (issue #54, 2026-08-21)

Issue #54's "jump to last red". The read pointer behind it is `unreadMarkerProvider` (see `wiki/providers_event_settings.md`); this file owns the placement and the rendering.

- `UnreadDivider({endInset, date})` -- an `hollow.error` rule with the app's OWN unread pill at its RIGHT end (filled `error`, white w700, radius 7 -- the same badge the sidebar and dock use for "unread"; bare red text was tried first and read as a stray word beside a red rule). Never centred: a centred label reads as another date separator.
- **`date` non-null MERGES the day separator into this rule** and `dateSeparatedChatRow` then skips `DateSeparator` entirely. Coming back the next day is the most ordinary way to meet this line, so the row almost always carries a date too, and stacked they were two full-width rules ~30px apart -- the same double-rule problem the own-message bar had against the scrollbar.
- Colours run through `Contrast.ensureContrast(error, background, 4.5)`; raw error red fails as small text on the light theme.
- The row is announced once, `Semantics(header: true, label: 'New messages[, <day>]')` over an `ExcludeSemantics`, so the merged day is still read out.
- **Jumping to it lives on the RAIL, and that is not a style choice.** A `ScrollablePositionedList` does not BUILD an off-screen row, so at the bottom of a long conversation the divider does not exist as a widget and nothing in the list could offer to take you to it. `ChatScrollRail.unreadRevIndex` (the REVERSED index) paints a `kRailUnreadMarkHeight` (3) pill on the track inside a `HollowPressable` `kRailUnreadSnap` (8) tall either way, and `_jumpFromPointer` snaps any tap within `kRailUnreadSnap` of the painted centre onto the message instead of the pointer's fraction. A drag that starts on the mark still drags: the track's drag recognizer beats a child's tap once the pointer moves.
- **`_unreadCentre` maps the message's position in the CONVERSATION onto the whole track**, not onto the thumb's travel the way the thumb does. The two agree in a long conversation and disagree exactly where the thumb mapping looks wrong: 21 messages, a thumb filling 85% of the track, and a run starting at the very top drew its mark halfway down (measured y=312 of a track running 130..545). Jumping stays exact either way -- `_jumpToUnread` goes to the index, at `alignment: 0.6` like the reply jump.
- Guards: `test/widget/unread_divider_test.dart`, four cases in `chat_scroll_rail_test.dart`, `test/screenshots/chat_separators_screenshot_test.dart` (all three separator shapes in both themes -- the merged one cannot be staged in a driven app, where every message lands today), and `scripts/probe_scenarios/fleet/unread_line.json` on two real instances.

## CPD-divergence convention

The channel pane calls the shared widgets through thin private wrappers (`_buildReplyPreviewBar()` etc.); the DM pane inlines the widget constructors in `_buildMessageArea`'s list. The differing call shapes keep the two build sequences token-divergent for Sonar CPD -- keep that asymmetry.
